    8.1. أدوات تطوير الويب

    نوضح هنا أين يمكن العثور على الأدوات اللازمة لتطوير الويب وكيفية تثبيتها. وقد تطورت إصدارات بعض الأدوات، وقد لا تكون الإرشادات الواردة هنا مناسبة للإصدارات الأحدث. لذا سيتعين على القارئ التكيف مع ذلك... في دورة البرمجة على الويب، سنستخدم بشكل أساسي الأدوات التالية، وجميعها متاحة مجانًا:

    • متصفح حديث قادر على عرض XML. تم اختبار أمثلة الدورة التدريبية باستخدام Internet Explorer 6.
    • مجموعة أدوات تطوير Java (JDK) حديثة. تم اختبار أمثلة الدورة باستخدام JDK 1.4. يأتي هذا JDK مزودًا بمكوّن Java الإضافي 1.4 للمتصفحات، مما يسمح لهذه الأخيرة بعرض تطبيقات Java الصغيرة التي تستخدم JDK 1.4.
    • بيئة تطوير Java لكتابة برامج servlet الخاصة بـ Java. وهنا نستخدم JBuilder 7.
    • خوادم الويب: Apache، PWS (خادم الويب الشخصي)، Tomcat.
      • سيُستخدم Apache لتطوير تطبيقات الويب بلغة PERL (Practical Extracting and Reporting Language) أو PHP (Personal Home Page)
      • سيتم استخدام PWS لتطوير تطبيقات الويب بلغة ASP (Active Server Pages) أو PHP
      • سيُستخدم Tomcat لتطوير تطبيقات الويب باستخدام سيرفلتات Java أو صفحات JSP (صفحات خادم Java)
    • تطبيق لإدارة قواعد البيانات: MySQL
    • EasyPHP: أداة تجمع بين خادم الويب Apache ولغة PHP و SGBD MySQL

    8.1.3. EasyPHP

    يتميز هذا التطبيق بكونه عمليًا للغاية، حيث يجمع في حزمة واحدة:

    • خادم الويب Apache (1.3.x)
    • لغة PHP (4.x)
    • SGBD MySQL (3.23.x)
    • أداة إدارة لـ MySQL: PhpMyAdmin

    8.1.6. Vbscript، Javascript، Perlscript

    هذه اللغات هي لغات برمجة نصية لنظام ويندوز. يمكنها العمل في بيئات مختلفة مثل

    • Windows Scripting Host للاستخدام المباشر في نظام Windows، لا سيما لكتابة نصوص برمجية لإدارة نظام
    • Internet Explorer. ويتم استخدامها في صفحات HTML حيث تضفي عليها تفاعلية معينة لا يمكن تحقيقها باستخدام لغة HTML وحدها.
    • Internet Information Server (IIS)، وهو خادم الويب الخاص بشركة مايكروسوفت على نظام NT/2000، ونظيره Personal Web Server (PWS) على نظام Win9x. في هذه الحالة، يُستخدم vbscript للبرمجة من جانب خادم الويب، وهي تقنية تسميها مايكروسوفت ASP (Active Server Pages).

    يمكن تنزيل ملف التثبيت من الرابط التالي: http://msdn.microsoft.com/scripting ثم اتباع الروابط الخاصة بـ Windows Script. يتم تثبيت ما يلي:

    • حاوية Windows Scripting Host، وهي حاوية تسمح باستخدام لغات برمجة نصية متنوعة، مثل Vbscript وJavascript، بالإضافة إلى لغات أخرى مثل PerlScript التي تأتي مع Active Perl.
    • مترجم VBscript
    • مترجم لغة Javascript

    8.2.1. العميل العام TCP

    تعمل العديد من الخدمات التي تم إنشاؤها في بدايات الإنترنت وفقًا لنموذج خادم الصدى الذي درسناه سابقًا: حيث تتم عمليات التبادل بين العميل والخادم عن طريق تبادل أسطر نصية. سنقوم بكتابة عميل TCP عام يتم تشغيله بالطريقة التالية: java cltTCPgenerique خادم المنفذ

    سيتصل هذا العميل TCP بالمنفذ port الخاص بالخادم serveur. وبمجرد القيام بذلك، سيقوم بإنشاء خيطين:

    1. خيط مسؤول عن قراءة الأوامر المكتوبة على لوحة المفاتيح وإرسالها إلى الخادم
    2. خيط آخر مسؤول عن قراءة الردود الواردة من الخادم وعرضها على الشاشة

    لماذا خيطان؟ كل خدمة TCP-IP لها بروتوكولها الخاص، وقد نواجه أحيانًا الحالات التالية:

    • يجب على العميل إرسال عدة أسطر من النص قبل الحصول على رد
    • قد تتضمن استجابة الخادم عدة أسطر من النص

    لذلك، فإن الحلقة التي تتمثل في إرسال سطر واحد إلى الخادم - واستلام سطر واحد مرسَل من الخادم - لا تكون مناسبة دائمًا. لذا سنقوم بإنشاء حلقتين منفصلتين:

    • حلقة لقراءة الأوامر المكتوبة على لوحة المفاتيح لإرسالها إلى الخادم. سيشير المستخدم إلى نهاية الأوامر باستخدام الكلمة الرئيسية fin.
    • حلقة لاستقبال وعرض ردود الخادم. وستكون هذه الحلقة حلقة لا نهائية لا تتوقف إلا بإغلاق تدفق الشبكة من قِبل الخادم أو من قِبل المستخدم عبر لوحة المفاتيح عند كتابة الأمر fin.

        String serveur=args[0];

    ننتقل الآن إلى خادم

    • يعرض على الشاشة الأوامر المرسلة من قبل عملائه
    • ويرسل إليهم كردّ الأسطر النصية التي يكتبها المستخدم على لوحة المفاتيح. وبالتالي، فإن المستخدم هو الذي يقوم بدور الخادم.

    يتم تشغيل البرنامج بواسطة: java serveurTCPgenerique portEcoute، حيث يمثل portEcoute المنفذ الذي يجب على العملاء الاتصال به. وسيتم توفير الخدمة للعميل بواسطة خيطين:

class ServeurSend extends Thread{
    // classe chargée de lire des réponses tapées au clavier
     // et de les envoyer à un client via un client tcp passé au constructeur

    Socket client;    // le client tcp
    int numClient;        // n° de client

     // constructeur
    public ServeurSend(Socket client, int numClient){
         // on note le client tcp
        this.client=client;
         // et son n°
        this.numClient=numClient;
    }//constructeur

     // méthode Run du thread
    public void run(){

        // données locales
        PrintWriter OUT=null;        // flux d'écriture réseau
        String réponse=null;        // réponse lue au clavier
    BufferedReader IN=null;    // flux clavier

        // suivi

         // gestion des erreurs

             // création du flux d'écriture réseau

      // création du flux clavier
      IN=new BufferedReader(new InputStreamReader(System.in));
            // boucle saisie-envoi des commandes

                 // identification client

                 // lecture réponse tapée au clavier

                // fini ?
